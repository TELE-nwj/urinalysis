# driver/walltime — 墙上时间（hh:mm:ss）

> 记录与屏显要的是"绝对时间"，而 `driver/time_svc` 只给单调毫秒 —— 本模块把两者接起来：
> **以 `time_svc` 的单调毫秒为尺子，显式记住一个起点，用"起点 + 经过的时间"推算墙上时间**。
> 唯一上层：`service/clock`（`clock_now_hms()` / `clock_sync_hms()`）。

## 1. 时间来源

| 情况 | 行为 |
|---|---|
| 未对时（当前默认） | `walltime_init()` 把起点设为 `00:00:00`，**本地起算并正常走时**；`walltime_is_synced()` 返回 0 |
| 已对时（后续 WiFi 上位机） | 上位机调用 `walltime_set_hms(hh, mm, ss)`，起点改为该时刻，之后继续靠 `time_svc` 走时；`walltime_is_synced()` 返回 1 |

正式方案由手机上位机下发对时（后续大概率走 WiFi）。上位机目前未接入，**所以 `walltime_set_hms()` 当前没有任何调用者**；接入时只需调它一次，本模块与上层都不用改。

## 2. 为什么不用 RTC / SNTP

1. 本板没有给 RTC 域供电的纽扣电池/VBAT，掉电后 RTC 一样归零，靠它拿不到真正的墙上时间；
2. SNTP/system time 需要联网，而且对时那一下会让系统时间**跳变** —— 记录时序与会话计时都建立在"时间只往前走"这个前提上，跳变会把它们搞乱；
3. `esp_timer` 单调递增、抖动小、不受对时影响，只当"尺子"，起点由外部给出。

## 3. 走时方式

```c
/* 当前当日秒数 = 起点秒数 + 起点之后经过的整秒，再对 86400 取模 */
elapsed_ms = timesvc_now_ms() - s_base_ms;
sec        = (s_base_sec + elapsed_ms / 1000) % 86400;
```

- 不自己每秒累加计数器：靠周期任务累加会受任务抖动与漏拍影响，误差越滚越大；读单调毫秒做差则误差不随时间累积。
- 取模带来两个正好需要的性质：跨天自动回到 `00:00:00`，返回值恒在 `0..86399` —— 调用方（屏显/记录）不用处理 `24:xx`。
- 状态只有三个变量：`s_base_sec`（起点当日秒数）、`s_base_ms`（起点单调毫秒）、`s_synced`。

## 4. 接口（`walltime.h`）

| 接口 | 说明 |
|---|---|
| `walltime_init()` | 清零并以当前时刻为计时起点（未同步，从 `00:00:00` 开始走） |
| `walltime_set_hms(hh, mm, ss)` | 对时：重置起点；`hh` 允许 0~23、`mm/ss` 允许 0~59，**越界按 24h 回绕**（负数也兜住） |
| `walltime_now_hms(buf, len)` | 取 `"hh:mm:ss"`；`buf` 至少 9 字节，不足时按 `snprintf` 截断、绝不越界 |
| `walltime_now_sec()` | 当日秒数 `0..86399`（当前无调用者） |
| `walltime_is_synced()` | 1 = 已被上位机对过时，0 = 本地起算（当前无调用者） |

## 5. 并发约定（本版）

代码求简，**读侧不加锁**：`walltime_set_hms()` 目前没有任何调用者（本版是预留接口）。若后续上位机在另一个任务里对时，需要重新评估 —— `set` 与取时并发时，取时可能读到"新起点 + 旧基准毫秒"的组合（错一次对时偏移量的量级）。接入时再按需加临界区，现在不为一个没有调用者的路径引入锁。

## 6. 被谁使用

`service/clock` 的 `clock_now_hms()` 每秒取一次（`app/monitor` 的 1 秒节拍）→ `service/screen` 推到屏上 `data.t6`。屏上时钟因此**上电即走**，未对时时从 `00:00:00` 开始。
