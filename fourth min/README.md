# fourth：ESP32-S3 尿量计固件（third + E 版写盘握手修复）

## 本工程是什么（2026-10-28）

以 `third` 为基线，把测试工程 `third_logtest_20261012` 的 **E 版写盘握手修复**保真合并进来。
`third` 本身**未改动**，仍保持 2026-10-12 的交付状态。

合并后的源码与测试版**逐字节一致**（11 个文件），只有工程名和本文件不同，便于两边对照。

## E 版修的是什么

真机上 CH376 写 U 盘出现过内容为空或损坏：`U0000001.TXT` 只有 1 字节 `2E`、
`U0000003.TXT` 首簇为 0 却有 56 字节长度、Windows 报错 1392。三轮排查的结论：

- **C 版**：会话保护 —— 暂停继续不换号，创建/恢复失败不自动重建
- **D 版**：加 FAT 保留项与双 FAT 首扇区预检、数据簇核验，但**实机失败**
- **D 失败原因**：`BYTE_WRITE` 返回 `0x1E`（芯片等待接收数据）时插入了读内部变量的探针，
  读到 `FILE` 等临时字节 → 误判地址异常 → **56 字节表头根本没发出去**
- **E 版修正**：数据交接阶段严格只走厂商流程（`0x1E → 0x2D → 0x3D → 0x14`），
  绝不插入任何诊断 SPI 命令；保留请求前的 FAT 检查、完成后的持久字段校验、关闭后回读

## 关于日志（2026-10-28 已清理）

测试版为了排查故障曾加了约 93 条调试日志（`[命令排查]`、`[建文件排查]`、`[写盘保护]` 等）。
**这些已全部删除**，日志输出与 `third` 原版保持一致：

- 各文件 `ESP_LOG` 数量与 third 相同：`ch376_spi.c` 50、`S1.c` 9、`main.c` 10、`monitor.c` 3
- `storage.c` 比 third 少 8 条，是因为对应代码分支被 E 版改写（如「文件不存在现场创建」分支已删）
- `ch376_diag.c` 是新增模块，**内部不含任何日志**（删日志时连带删掉了 2 个纯日志函数）
- CH376 日志级别保持 third 原版的 `ESP_LOG_WARN`
- 固件体积因此从 847,536 B 降到 831,472 B（仅比 third 的 829,424 B 多 2 KB）

## ⚠ 两处仍需注意

1. **每次写分钟都重挂载 + 逐字节回读** —— 一次写盘要重挂载两次，临界区比 third 明显变长。
   这是 E 版验证「数据真的落盘」的核心手段，不建议去掉。
2. **拦截比 third 严格** —— 磁盘挂载失败直接失败、文件缺失禁止现场重建、长度异常拒绝追加。
   能防止覆盖历史记录，但 U 盘接触不良时会更早地停止写盘。

## 目录与层级

- `main/main.c`：入口及初始化编排，依次准备服务、手机适配器和 monitor。
- `main/app/`：monitor 唯一状态执行器、S1 测量、S2 暂停、手机适配。
- `main/service/`：计量、时钟、屏显、按键、电量、存储和手机协议。
- `main/driver/`：硬件、SoftAP 和 WebSocket 驱动。
- `main/bsp/`：公共错误码与板级引脚定义。
- `firmware/`：本工程真实构建产生的匹配镜像、偏移参数和 SHA256 校验清单。
- `build/`：本目录本地构建输出，不从其他工程复制 CMake 缓存。
- `reports/`：构建日志、源码一致性校验及交付验证记录。

## 本机编译

在 PowerShell 执行：

```powershell
Set-Location 'F:\ESP32\niaio\git\third'
.\build.ps1
```

脚本使用 `idf-env.ps1` 指定的已安装 ESP-IDF 5.5.5、Python 和 Xtensa 工具链，
显式指定本工程 `-C`、本目录 `build/` 和 `IDF_TARGET=esp32s3`。工程开启
`MINIMAL_BUILD`，避免构建无关 LCD 组件。主程序为 `build/third.bin`。
其他电脑须按实际安装位置调整 `idf-env.ps1`。

## 烧录

必须先识别板子的**实际 ESP32-S3 下载串口**，然后通过 `-Port` 明确传入。
不自动扫描、猜测或打开串口；COM21 是已知 CH340 日志口，不能据此认定下载口。

使用本目录最近一次构建的镜像：

```powershell
.\flash.ps1 -Port COM7  # COM7 仅为示例，请替换为已确认的下载串口
```

使用随本目录交付的已编译镜像，无需先重新构建：

```powershell
.\flash.ps1 -Port COM7 -UsePrebuilt  # COM7 仅为示例
```

上面的 COM7 需替换成实际串口名；仅在确认下载口为 COM7 后才传入 `-Port COM7`。
脚本先检查 ESP32-S3 构建元数据和所有镜像，再从相应目录读取实际 `flash_args`。
默认波特率 460800，可通过 `-Baud` 调整。交付期间未执行本脚本、未烧录、未占串口。

默认镜像参数为 DIO、80 MHz、2 MB Flash；偏移以实际 `firmware/flash_args` 为准：

| 偏移 | 镜像 |
| --- | --- |
| `0x0` | `bootloader/bootloader.bin` |
| `0x8000` | `partition_table/partition-table.bin` |
| `0x10000` | `third.bin` |
