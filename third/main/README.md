# 两键尿量检测器固件

工程位置：`F:\ESP32\niaio\git\second sol`。目标芯片 ESP32-S3，ESP-IDF v5.5.5。串口屏是**纯显示设备**（单片机只发不收）；GPIO8、GPIO9 两个实体按键控制测量，软件只做三态状态机（待开始 / 测量中 / 暂停）。

## 代码结构

| 层 | 位置 | 职责 |
|---|---|---|
| 入口（组合根） | `main.c` | 只调 service 的 init：`clock_init` / `urine_capture_init` / `screen_init` / `power_init` / `storage_init`，然后启动 `app_monitor_start()`；本文件不 include 任何 driver 头 |
| 应用 | `app/monitor`、`app/S1`、`app/S2` | `monitor` 是三态主体（20 ms 主循环、按键、1 秒节拍、报警栏唯一写者）；`S1` 测量中（会话计时、24 h 结论、每分钟写盘、200 ms 推屏）；`S2` 暂停（结算 + 冻结数值） |
| 服务 | `service/urine`、`screen`、`storage`、`power`、`clock`、`input` | app 层唯一可见的接口面；各模块的硬件初始化（UART/ADC/GPIO）在各自 `*_init()` 内完成 |
| 驱动 | `driver/drop`、`key`、`screen_uart`、`ch376`、`time_svc`、`walltime`、`battery` | GPIO 中断、UART、软 SPI、单调时基、墙上时间、ADC 分压 |
| 板级 | `bsp/pin_map.h`、`bsp/err.h` | 引脚/外设号与通用错误码 |

依赖方向固定为 `main → app → service → driver → bsp`，不反向、不跨层。原来的 `app/S3`、`app/S4` 已删除，其功能拆入 `monitor`（报警栏/1 秒节拍）与 `S1`（测量期处理）。

## 操作

| 当前状态 | 按键 1（GPIO8） | 按键 2（GPIO9） |
|---|---|---|
| 待开始 | 分配新测量文件 → 清数据 → 打开滴落中断 → 计时基准=此刻，进入**测量中**（状态栏随后变 `start`） | **复位**（待开始下也执行，状态栏刷成 `reset`） |
| 测量中 | 排空滴间隔 → 结算计时到此刻 → 数值冻结到屏 → 关滴落中断，进入**暂停**（状态栏随后变 `stop`） | 复位到待开始，状态栏刷成 `reset` |
| 暂停 | 计时基准=此刻（暂停期间不计时）→ 重开滴落中断，回到**测量中**（状态栏随后变 `start`） | 复位到待开始，状态栏刷成 `reset` |

- 按键低有效（内部上拉），连续 3 次采样一致才认一次（20 ms 周期 ≈ 60 ms 消抖），**按住不连发**，无长按/双击。
- 复位在任何状态（含待开始）都执行：停采集 → 清滴数 → 关本次文件 → 数据与计时归零 → 4 个数值控件归零 → 状态回到待开始（状态栏刷成 `reset`）。待开始时也执行，是为了让屏端 HMI 页面与 MCU 停在同一个界面。
- 状态与状态栏命令字的对应：待开始 = `reset`、测量中 = `start`、暂停 = `stop`。**按键不直接发屏指令**，只改状态机；文本由 `ui_sync()` 在下一个 20 ms 循环按变化补发（无独立的事件指令通道）。

## 计量、提示与记录

- 每滴默认 `0.5 ml`（`URINE_DROP_ML_DEFAULT`，`service/urine/urine.h`），**必须按实物标定**。GPIO10 检测上升沿，0.5 秒内的重复边沿被过滤。
- 会话计时是**有效测量时长**（暂停不计时），不是墙钟时间。实时速率按最近一次有效相邻间隔换算（`3600 × 每滴ml ÷ 间隔秒`），7 秒（`URINE_RATE_ZERO_MS`）无新滴归零。
- 报警栏 `data.t5` 发**单字母**（`A`=正常 / `B`=无尿 / `C`=少尿 / `D`=多尿 / `E`=尿袋满），**每秒发一次**（1 秒节拍）：`B/C/D` 来自首个 24 小时结论（`<100 ml` 无尿、`<400 ml` 少尿、`>2500 ml` 多尿，满 24 小时那一刻判定一次并锁定）；`E` 只在累计尿量**首次达到 2000 ml**（`URINE_BAG_FULL_ML`）时插播 1 分钟，随后回到本该显示的字母，K2 复位会取消该窗口。
- 状态 3 态（`待开始` / `测量中` / `暂停`）由状态栏控件 `data.t4` 以**命令字**表达：`reset` / `start` / `stop`（屏端可显示也可做条件判断）。U 盘异常不上屏（只留串口日志与每 5 秒重试）。
- **1 秒节拍与是否测量无关**：上电就开始，按 `clock_ms()` 的**绝对时刻**判定（`TICK_MS = 1000u`，与 `s_next_tick_ms` 比较后用加法推进；环内偶发阻塞只推迟当次、不累积漂移，被阻塞超过一整拍就跳到下一个未来时刻、不补发），每秒推一次时钟（`data.t6`）、电量（`data.t7`）与报警栏（`data.t5`，见上）。
- 每次新测量分配一个独立文件，从 `/U0000001.TXT` 起按编号扫描已存在的文件（大写 8.3，CH376 只认大写 8.3）。每个整分钟写入一行：`时间(hh:mm:ss)  本分钟尿量(ml)  本分钟平均流速(ml/h)`，平均流速 = 本分钟尿量 × 60。
- 无 U 盘仍可计量：不写盘、每 5 秒重试一次，恢复后从当前分钟继续；缺失的分钟不缓存、不补写。暂停后继续写同一文件。
- 电量：见 `service/power`——分压比 2.0（`R59=200k` / `R60=200k`，`R61=1k` 限流，`C13=100nF`），电压→电量是 12 点分段线性查表，**必须实机标定**；未采到有效电压时屏上显示 `--`。
- 时间：`driver/walltime` 维护墙上时间，未对时时从 `00:00:00` 起走；`clock_sync_hms()` / `walltime_set_hms()` 是留给后续 WiFi 上位机对时的**预留接口**（当前无调用者）。

屏上的完整通信格式（8 个控件、唯一的 `FF FF FF` 结尾）见工程根目录的《单片机与串口屏通信格式.md》。

## 构建

本工程根目录的构建走独立构建目录 `build-sol`（`main/` 下的旧 `build/` 缓存指向参考工程，不要复用）：

```bat
REM 在已激活 ESP-IDF v5.5.5 的终端里，于工程根目录执行：
idf.py -B build-sol build
```

`flash.bat`（工程根目录）固定了工程目录、SDK 路径与 `build-sol`，默认串口 COM12，可传参覆盖：`flash.bat COM5`。**仅在连接实机并确认串口后运行**。
