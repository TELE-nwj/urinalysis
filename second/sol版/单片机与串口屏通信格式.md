# 单片机与串口屏通信格式（两键版）

本文对应 `second sol` 固件与 HMI 工程（`F:\ESP32\niaio\UI` 下的横屏界面）。实体按键负责开始 / 暂停 / 继续 / 复位；串口屏是**纯显示设备**，固件不接收、不解析屏发来的任何数据。

## 1. 接线与串口参数

| 项目 | 设置 |
|---|---|
| MCU | ESP32-S3（ESP32-S3-WROOM-1-N16R8） |
| 串口 | UART1，115200 bit/s，8 数据位、无校验、1 停止位、无流控 |
| MCU TX → 屏 RX | GPIO17 |
| MCU RX ← 屏 TX | GPIO18（固件不读此方向，引脚仍绑定，便于硬件排查） |
| 实体按键 | 按键 1：GPIO8；按键 2：GPIO9；低电平按下、内部上拉 |
| 日志口 | UART0（USB 串口，115200） |

串口屏与 MCU 必须共地。引脚定义见 `main/bsp/pin_map.h`（`BSP_PIN_UART_SCREEN_TX/RX`、`BSP_UART_SCREEN_BAUD`）。

## 2. 指令格式（**全工程只有一种**）

固件发往屏的指令**只有一种**，所有控件（包括状态栏）都用它：

```text
<控件名>.txt="内容"  +  FF FF FF
```

- 结尾字节固定是 **3 个 `0xFF`**（`screen.c` 的 `s_txt_end[3]`），没有别的结尾形式
- 页切换 `page 0` 也属于这一类，同样以 `FF FF FF` 结尾
- **没有第二条通道**：早期设计过的 `@start` / `@stop` / `@reset` + `\r\n` 事件指令**已按用户要求取消**（`screen_notify_*()` 等已从固件删除），状态改由状态栏控件承载（见 §4）

举例：

```text
data.t0.txt="12.5"  FF FF FF      ← 累计尿量
data.t4.txt="start" FF FF FF      ← 状态栏：命令字(测量中)
data.t6.txt="18:30:05" FF FF FF   ← 实时时间
```

## 3. 控件映射（8 个）

控件名来自 `main/service/screen/screen.h` 的 `SCR_CTRL_*` 宏 —— 这是固件与 HMI 工程之间的**唯一约定**：

| 宏 | 控件名 | 含义 | 屏上内容 | 发送函数 |
|---|---|---|---|---|
| `SCR_CTRL_URINE` | `data.t0` | 累计尿量 | mL，1 位小数（如 `12.5`） | `screen_show_urine()` |
| `SCR_CTRL_RATE` | `data.t1` | 实时速率 | mL/h，1 位小数（如 `180.0`） | `screen_show_rate()` |
| `SCR_CTRL_DROPS` | `data.t2` | 累计滴数 | 整数（无小数点） | `screen_show_drops()` |
| `SCR_CTRL_ELAPSED` | `data.t3` | 运行时间（会话计时） | `hh:mm:ss` | `screen_show_elapsed()` |
| `SCR_CTRL_STATUS` | `data.t4` | 状态栏 | **命令字** `reset` / `start` / `stop`（见 §4） | `screen_show_status()` |
| `SCR_CTRL_ALERT` | ⚠ `data.t5` | 报警栏 | **单字母** `A`~`E`（见 §5） | `screen_show_alert()` |
| `SCR_CTRL_CLOCK` | `data.t6` | 实时时间 | `hh:mm:ss` | `screen_show_clock()` |
| `SCR_CTRL_BATTERY` | `data.t7` | 电量 | `85%`；未采到有效电压时 `--` | `screen_show_battery()` |

> - **状态栏的内容是命令字，不是中文**：`reset` / `start` / `stop` 三个 ASCII 词，屏端既可直接显示（配好映射），也可拿它做条件判断。原来的三态中文（`待开始`/`测量中`/`暂停`）不再经过串口。
> - 前缀固定为 `data.`，**编号一律以 `screen.h` 的 `SCR_CTRL_*` 宏为准** —— 旧版的 `data.n0/n1/n2` 与更早的编号已全部作废，不要在 HMI 工程里沿用。将来改控件名只改 `screen.h` 这 8 个宏，其余代码与本文的对应关系不变。
> - ⚠ **报警栏 `data.t5` 是占位 id：该栏 HMI 工程尚未制作**，做好后按实际控件名替换宏值即可；其余 7 个控件（含状态栏 `data.t4`）已由 HMI 工程定稿。烧录前仍建议在实际 HMI 工程中核对页面与控件名（尤其是 `data.` 前缀）。背景图上的固定标签不是 MCU 动态发送的。

### 上电初始化序列

`screen_init()` 依次发出（顺序与 `screen.c` 的调用顺序一致，共 **9 帧** = 首页 1 帧 + 8 个控件各 1 条）：

```text
page 0                                    ← 切到首页(主界面 = page0)
data.t0.txt="0.0"        FF FF FF         ← 累计尿量归零
data.t1.txt="0.0"        FF FF FF         ← 实时速率归零
data.t2.txt="0"          FF FF FF         ← 累计滴数归零
data.t3.txt="00:00:00"   FF FF FF         ← 会话计时归零
data.t4.txt="reset"      FF FF FF         ← 状态栏初值：待开始
data.t5.txt="A"          FF FF FF         ← 报警栏初值(占位控件；A=正常)
data.t7.txt="--"         FF FF FF         ← 电量尚未采样
data.t6.txt="00:00:00"   FF FF FF         ← 时钟未对时
```

## 4. 状态栏：命令字与状态对应

状态栏 `data.t4` 的内容是**命令字**，由 `app/monitor` 的 `status_text()` 产生，`ui_sync()` 按"内容变化"推送：

| 命令字 | 对应状态 | 触发时机 |
|---|---|---|
| `reset` | 待开始（`APP_IDLE`） | 上电初始化；K2 复位后 |
| `start` | 测量中（`APP_MEASURING`） | K1 开始测量；K1 从暂停继续 |
| `stop` | 暂停（`APP_PAUSED`） | K1 测量中按下暂停 |

- **按键不直接发任何屏指令**：K1/K2 只改状态机状态，状态栏文本由 `ui_sync()` 在**下一个 20 ms 循环**里按变化补发（最坏延迟 20 ms，肉眼不可见）。
- 屏端可以：① 直接把这三个词显示（如 `start` → 显示"测量中"可用屏端自己的映射/控件），或 ② 用它们做条件判断（例如按状态切换页面元素）。**约定以命令字为准，不要在屏端反向解析中文状态词**。
- 复位在任何状态（含待开始）都执行并把状态栏刷成 `reset`，屏端据此回到待开始界面。

## 5. 报警栏取值（单字母，三种发送时机）

### 报警栏 `data.t5`（**占位控件**）

内容是**单字母**（ASCII）：

| 字母 | 含义 | 发送时机 |
|---|---|---|
| `A` | 正常 | **一直发送**：由 1 秒节拍每秒发一次（与时钟/电量同节拍），不依赖内容变化 |
| `B` | 无尿 | 首个 24 小时结论 `< 100 ml`；满 24 小时锁定后持续有效 |
| `C` | 少尿 | 首个 24 小时结论 `≥ 100 ml` 且 `< 400 ml`；锁定后持续有效 |
| `D` | 多尿 | 首个 24 小时结论 `> 2500 ml`；锁定后持续有效 |
| `E` | 尿袋满 | **只在"累计尿量首次达到 2000 ml"时插播 1 分钟**（`ALERT_BAG_FULL_MS = 60000`），随后回到本该显示的字母 |

规则细节：

- **E 优先但不持久**：1 分钟插播窗口内显示 `E`，窗口结束后回到 `B/C/D/A` 中本该显示的那个。
- **上升沿触发**：满袋标志 `flag_bag_full` 一旦置 1 就不会自己回落（累计尿量只增），所以固件用 0→1 的**上升沿检测**决定是否开窗口 —— 否则 `E` 会被一直刷下去。
- **K2 复位会取消进行中的 E 窗口**，边沿检测重新起算（下次再达到 2L 才再插播一次）。
- 待开始（含复位后）固定为 `A`。
- 屏端负责把字母映射成要显示的内容（中文、图标、颜色都行）。

首个 24 小时结论在累计**有效测量时间**达到 24 小时那一刻判定一次并锁定（不随后续尿量重新判定）。判定阈值在 `main/app/S1/S1.c`：`DAY_ANURIA_ML = 100.0f`、`DAY_OLIGURIA_ML = 400.0f`、`DAY_POLYURIA_ML = 2500.0f`。

状态栏是**内容变化才发**，报警栏是**每秒都发**（见 §6）—— 两者节奏不同是有意设计：报警栏要保证屏上始终有值。

> U 盘异常**不上屏提示**：原先"每 5 秒插播 1 秒 `U盘异常`"的做法已删除，U 盘不可用只体现在串口日志与每 5 秒的重试里。

## 6. 刷新节奏

| 通道 | 内容 | 节奏 |
|---|---|---|
| 1 秒节拍 | `data.t6`（时钟）+ `data.t7`（电量）+ `data.t5`（报警栏） | **上电即跑，与是否测量无关**；按 `clock_ms()` 的**绝对时刻**判定（`TICK_MS = 1000u`，加法推进、阻塞只推迟当次），每秒各一帧；报警栏每秒都发（`A` 一直发） |
| 测量中推屏 | `data.t0` / `data.t1` / `data.t2` / `data.t3` | 节流 200 ms（20 ms 主循环下约 5 Hz），避免刷爆串口屏 |
| 变化即发 | `data.t4`（状态栏） | 内容变化时一条 |
| 状态转换 | `data.t4` | 按键只改状态机，文本由 `ui_sync()` 在下一个 20 ms 循环补发 |

实时速率：按最近一次有效相邻间隔换算（`3600 × 每滴ml ÷ 间隔秒`）；距最近一滴超过 7 秒（`URINE_RATE_ZERO_MS = 7000`）显示 `0.0`，避免屏上停在旧读数。

## 7. 电量：分压与电压→电量对照

### 硬件分压网络（见 `main/bsp/pin_map.h`）

```text
BAT ──R59(200k)──┬──R61(1k)── ADC(GPIO7 = ADC1_CH6)
                 │
               R60(200k)      C13(100nF)
                 │               │
                GND             GND
```

- 采样节点电压 = `V_bat × R60/(R59+R60)` = `V_bat × 200/400` = **V_bat / 2**
- 所以 **`V_bat = V_adc × 2`**（`BSP_BATTERY_DIV_NUM = 400u` / `BSP_BATTERY_DIV_DEN = 200u`）
- `R61(1k)` 是 ADC 前的限流电阻，ADC 输入高阻，不参与分压计算；`C13(100nF)` 为滤波电容
- 满电 4.2 V → 2.1 V 入 ADC；放空 2.7 V → 1.35 V，均在 12 dB 衰减量程内
- 驱动内部连采 **16 次**（`BATTERY_SAMPLE_TIMES`）取平均再换算；`ADC_ATTEN_DB_12` 校准不可用时退化为线性换算（满量程 3100 mV / 4095）并告警

### 电压 → 电量（12 点分段线性查表，`main/service/power/power.c`）

| 电池端电压 mV | 电量 % |
|---|---|
| 4200 | 100 |
| 4050 | 90 |
| 3950 | 80 |
| 3870 | 70 |
| 3820 | 60 |
| 3800 | 50 |
| 3770 | 40 |
| 3740 | 30 |
| 3700 | 20 |
| 3600 | 10 |
| 3400 | 5 |
| 3000 | 0 |

- 表按电压降序排列，区间内做线性插值；高于表顶按 100%、低于表底按 0%。
- 采样周期 1 秒（`POWER_POLL_PERIOD_MS = 1000`），先做一阶低通滤波（`α = 0.3`）再查表，避免带载瞬时压降让百分比来回跳。
- 滤波之后还有一道**"水位"钳制：电量显示单调不增** —— 一旦屏上显示出某个百分比，之后只会持平或下降，绝不会因电压波动而回升（`power_poll()` 里只有新值更低才更新 `s_pct`；`s_pct < 0` 表示还没显示过，首个有效值直接采用）。这样不会出现"越用越多"的观感。
  > ⚠ **副作用**：换电池或充电后电量虽真实回升，显示会**停在水位上**（需重新上电恢复）。`power_init()` 会把水位复位成 -1，所以**重新上电即可恢复真实读数**。
- 滤波后电压低于 `2500 mV`（`POWER_MV_VALID_MIN`，给保护板 2.7 V 留余量）视为**无效读数**：整次采样丢弃，屏上保持上一次的值；从未采到过有效值时显示 `--`。
- ⚠ **表中数值是按 126280 锂聚合物电池（10000 mAh，标称 3.8 V，充电截止 4.20 V，保护板放电保护 2.7 V）资料推算的，必须实机标定后定稿**：未标定前只保证"电压↔电量单调"，绝对值可能差 ±10% 量级。标定方法：用可调电源从 4.20 V 起按 0.1 V 步进下调，每档静置后记录屏显电压，与恒流放电的 Ah 积分对应，逐个替换表中的 mV/percent 对。

## 8. 实时时间 `data.t6`

`driver/walltime` 维护墙上时间（`hh:mm:ss`），以 `driver/time_svc` 的单调毫秒为基准累加，跨天自动对 86400 取模。**未对时状态下从 `00:00:00` 本地起算并正常走时**，屏上不会出现 `24:xx`。

正式方案由手机上位机下发对时（后续大概率走 WiFi）：接入后调用 `walltime_set_hms()`（或经 `service/clock` 的 `clock_sync_hms()`）即可切换到真实时刻，本模块与上层代码都不用改。**该接口目前是预留的，固件中没有调用者。**

## 9. 屏 → MCU 方向（无）

本版**没有屏幕操作命令**：固件不注册 UART 接收回调，也不创建接收任务。`uart_driver_install()` 虽然分配了 256 字节 RX 缓冲（IDF 要求 `rx_buffer_size` 必须大于硬件 FIFO，不能传 0），但**固件从不读取它** —— `driver/screen_uart` 里没有 `uart_read_bytes`、没有 RX 事件，屏端发来的字节只会把这块缓冲填满后被驱动丢弃。屏端即使发送旧的 `@用户名@login/start/stop/reset`，MCU 也不会据此改变状态。

实际操作由 GPIO8、GPIO9 两个实体按键完成（**按键不直接发屏指令**，只改状态机，状态栏文本随后由 `ui_sync()` 补发）：

| 当前状态 | 按键 1（GPIO8） | 按键 2（GPIO9） |
|---|---|---|
| 待开始 | 开始测量（状态栏随后变 `start`） | 复位（状态栏刷成 `reset`） |
| 测量中 | 暂停（状态栏随后变 `stop`） | 复位（状态栏刷成 `reset`） |
| 暂停 | 继续测量（状态栏随后变 `start`） | 复位（状态栏刷成 `reset`） |

按键稳定按下触发一次，按住期间不连发（无长按/双击）。

## 10. 排查用日志

每一帧发往屏的数据都会在**日志串口**打印一行，只打印可见内容、不含结尾字节（结尾字节见 §2）：

```text
I (1234) screen: [SCR] data.t0.txt="12.5"
I (1300) screen: [SCR] data.t4.txt="start"
```

用日志可以逐行核对屏上实际收到的内容；日志缺失说明该帧根本没发出去（发送失败会另打 `ESP_LOGE`）。

## 11. 中文显示注意事项

**屏上没有任何 MCU 动态发送的中文**：状态栏发命令字（`reset` / `start` / `stop`），报警栏发字母（`A`~`E`），都是 ASCII 单字节。

因此中文显示全部由屏端负责：TJC 工程需要自己维护"命令字/字母 → 中文"的映射，并保证**字库包含要显示的所有词** —— 状态三态（`待开始` / `测量中` / `暂停`）与报警五态（`正常` / `无尿` / `少尿` / `多尿` / `尿袋满`）都是屏端自己显示的文字，不经过串口。若实机出现乱码，只需调整屏端字库/编码设置，固件侧不需要改动。
