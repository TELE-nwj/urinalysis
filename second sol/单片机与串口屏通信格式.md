# 单片机与串口屏通信格式（两键版）

本文对应 `second sol` 固件和 `F:\ESP32\niaio\UI` 下的横屏界面。实体按键负责开始、暂停、继续和复位；串口屏只接收 MCU 的显示指令，不再向 MCU 发送 `@用户名@命令`。

## 1. 接线与串口参数

| 项目 | 设置 |
|---|---|
| MCU | ESP32-S3 |
| 串口 | UART1，115200 bit/s，8 数据位、无校验、1 停止位、无流控 |
| MCU TX → 屏 RX | GPIO17 |
| MCU RX ← 屏 TX | GPIO18；固件不解析此方向数据，可保留物理接线 |
| 实体按键 | 按键 1：GPIO8；按键 2：GPIO9；低电平按下，内部上拉 |

串口屏与 MCU 必须共地。上电初始化时，MCU 发送 `page 0`，随后写入各显示控件的初始值。

## 2. MCU → 串口屏帧格式

每条指令由 ASCII 指令文本和三个结束字节组成：

```text
<指令文本> FF FF FF
```

例如，累计尿量为 12.5 ml 时，文本部分为 `data.n0.txt="12.5"`，后面紧跟字节 `FF FF FF`。结束字节不是可打印字符，也不附加回车换行。

文本控件使用 `控件名.txt="内容"`，页面切换使用 `page 0`。数值和滴数按文本发送，不使用 `.val`。

## 3. 页面与控件

| 显示区 | TJC 控件 | MCU 发送示例 | 单位或格式 |
|---|---|---|---|
| 累计尿量 | `data.n0` | `data.n0.txt="12.5"` | ml，1 位小数 |
| 实时速率 | `data.n1` | `data.n1.txt="180.0"` | ml/h，1 位小数；7 秒无新滴归零 |
| 累计滴数 | `data.n2` | `data.n2.txt="25"` | 滴，整数 |
| 运行时间 | `data.t1` | `data.t1.txt="01:23:45"` | 有效测量时间 `hh:mm:ss`，暂停不计时 |
| 状态／警报 | `data.t0` | `data.t0.txt="测量中"` | 见下表 |

这些控件名是当前固件中的发送目标。烧录前应在实际 HMI 工程中核对页面与控件名，尤其是 `data.` 前缀。背景图中的固定标签不是 MCU 动态发送的。

测量中由 `monitor` 每 20 ms 调度；数值与时间约每 200 ms 刷新一次。状态文本只在内容变化时发送。按键造成的状态变化和复位清零会立即发送。

## 4. 状态／警报文本

| 发送文本 | 条件 |
|---|---|
| `待开始` | 上电或复位后 |
| `测量中` | 正在测量，无其他提示 |
| `暂停` | 按键 1 暂停；数值和时间冻结 |
| `U盘异常` | 正在测量但 U 盘不可写；固件仍继续计量并周期重试 |
| `无尿` | 首个 24 小时有效测量尿量 `<100 ml` |
| `少尿` | 首个 24 小时有效测量尿量 `≥100 ml` 且 `<400 ml` |
| `多尿` | 首个 24 小时有效测量尿量 `>2500 ml`，且未显示满袋组合状态 |
| `尿袋满` | 本次测量累计尿量 `≥2000 ml` |
| `尿袋满/多尿` | 满袋且首个 24 小时判定为多尿 |

首个 24 小时结论在累计有效测量时间达到 24 小时后固定，不随其后的累计量重新判定。暂停时优先显示 `暂停`，继续测量后恢复尿量提示。测量中以满袋及满袋／多尿组合、24 小时尿量结论、正常测量为主状态；U 盘异常时每 5 秒插播 1 秒 `U盘异常`，保证与临床提示同时存在时也能看到存储故障。

固件源文件中的中文字符串以 UTF-8 字节通过 UART 发送。TJC 实际工程须配置能显示这些动态中文文本的字库和字符编码；若实机出现乱码，应调整屏端字符设置或在通信适配层转换编码，并重新核对本表。

## 5. 屏 → MCU 方向

新版没有屏幕操作命令。固件不注册 UART 接收回调，也不创建 `uart_rx` 任务。屏端即使发送旧的 `@用户名@login/start/stop/reset`，MCU 也不会据此改变状态。

实际操作由 GPIO8、GPIO9 两个实体按键完成：按键 1 在待开始时开始、在测量中暂停、在暂停时继续；按键 2 在测量或暂停时复位。长按不会重复触发。
