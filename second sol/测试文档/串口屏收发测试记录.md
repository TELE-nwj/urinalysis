# 测试日志 — 串口屏收发测试记录

> 累计记录，新测试**追加**到本文档末尾，不要覆盖历史条目。

> ## ⚠️ 历史说明（先读）
>
> 第 1~6 条（T1~T6）记录的是 **2026-09-14 的旧版固件**：那时屏端会向 MCU 发 `@用户名@命令`，
> MCU 侧有接收链路（UART 接收回调 + 接收任务 + 同步读接口）。**这些收发相关的 API 在两键版中已全部删除**：
>
> - 同步读接口、接收回调注册接口、RX 任务：已删除，`driver/screen_uart` 现在**只发不收**（分配了 256 字节 RX 缓冲，但固件从不读取、无接收任务）。
> - 旧版发送"运行时间"的那个函数：已更名为 `screen_show_elapsed()`（同一个控件，现为 `data.t3`）。
> - 旧版控件宏（`CTRL_*`）：已更名为 `SCR_CTRL_*`；**控件编号也全部换过一遍**（旧 `data.n0/n1/n2`、`data.t0~t4` 已作废），以 §0 的当前控件表为准。
>
> 历史条目里的现象、根因与结论（行尾字节、大写 8.3 文件名、`0x30`+`0x31`、落盘验证）**仍然有效**，
> 因此保留为留档；其中涉及已删除接口的代码片段仅作历史参考，**不要照抄**。
> 当前通信格式见工程根目录《单片机与串口屏通信格式.md》。

## 0. 测试环境（每次测试请先核对）

| 项 | 值 |
|---|---|
| 板卡 | ESP32-S3（WROOM-1-N16R8） |
| SDK | ESP-IDF v5.5.5 |
| 串口屏 | 淘晶驰 TJC / Nextion 类 |
| 通讯口 | UART1，115200 8N1 |
| 引脚 | MCU TX = `GPIO17` → 屏 RX；MCU RX = `GPIO18` ← 屏 TX（见 `main/bsp/pin_map.h`） |
| 日志口 | UART0（USB 串口，115200） |
| U 盘 | CH376 正常读写：每次新测量建 `/U0000001.TXT` 等，测量中每分钟追加一行 |

### 当前控件对照（`main/service/screen/screen.h` 的 7 个 `SCR_CTRL_*` 宏；前缀固定 `data.`）

| 宏 | 控件名 | 含义 |
|---|---|---|
| `SCR_CTRL_URINE` | `data.t0` | 累计尿量 ml |
| `SCR_CTRL_RATE` | `data.t1` | 实时速率 ml/h |
| `SCR_CTRL_DROPS` | `data.t2` | 累计滴数 |
| `SCR_CTRL_ELAPSED` | `data.t3` | 运行时间（会话计时，文本 `hh:mm:ss`） |
| `SCR_CTRL_CLOCK` | `data.t6` | 实时时间 `hh:mm:ss` |
| `SCR_CTRL_BATTERY` | `data.t7` | 电量（如 `85%`；未就绪 `--`） |
| `SCR_CTRL_ALERT` | ⚠ `data.t5` | 报警栏：单字母 `A`~`E`（`A` 正常 / `B` 无尿 / `C` 少尿 / `D` 多尿 / `E` 尿袋满）；**占位，HMI 尚未制作** |

> - 旧版的 `data.n0` / `data.n1` / `data.n2` 与 `data.t0~t4` 已**全部作废**，不要在 HMI 工程里沿用。
> - **状态栏也是文本控件**：`data.t4`，内容是命令字 `reset` / `start` / `stop`（`reset` = 待开始、`start` = 测量中、`stop` = 暂停），由 `app/monitor` 在状态变化时推送。

### 当前帧格式与指令（**只有一种指令格式**）

| 方向 | 组帧 | 结尾字节 |
|---|---|---|
| MCU → 屏（全部指令） | `<控件名>.txt="值"`（页切换为 `page 0`） | `FF FF FF` |
| 屏 → MCU | **无**：固件不接收、不解析屏数据 | — |

> 早期设计过的 `@start` / `@stop` / `@reset` + `\r\n` 事件指令**已取消**，固件里不再有第二条通道。

## 1. T1 — 主函数直接读串口（**旧版接收链路，已删除**）

- **日期**：2026-09-14
- **代码位置**：旧版 `main/main.c` → `app_main()` 主循环 ①
- **目的**：确认 MCU 能收到屏发来的数据，并确认**行尾字节**到底是 `\r\n` / `\n` / `\r`。
- **当时的做法**：在 `app_main()` 里用旧版的同步读接口轮询 UART（每次 50 ms 超时），把收到的原始字节
  用 `ESP_LOG_BUFFER_HEXDUMP` 打出来核对。

> ⚠️ 当时测试期间**不调用 `screen_init()`**：旧版的接收回调注册接口会建一个接收任务把 UART 数据读走，
> 主循环就读不到字节了。本版已无接收链路，这条注意事项随之作废。

### 预期现象

```
I (xxxx) main: 串口屏 RX 15 字节
I (xxxx) main: 40 45 ... 0d 0a
I (xxxx) main: 文本: @用户名@login..
```

- hex 行能直接看出行尾是 `0D 0A`
- 文本行的 `.` 表示不可见字符，`@用户名@命令` 一眼可读

### 结果

- [x] **合格**（用户确认）—— **结论沿用至今：屏端发出的行尾是 `0D 0A`**。
  （该结论服务的是"屏 → MCU"的旧双向协议，本版已不接收屏数据；现在发往屏的指令一律以 `FF FF FF` 结尾。）

## 2. T2 — 主函数每秒发送数据（**旧版 5 控件发送链路**）

- **日期**：2026-09-14
- **目的**：验证 MCU → 屏的控件刷新是否正常（值变化 + 状态切换）。
- **当时的做法**：用节拍计时（`xTaskGetTickCount()`）保证 1 秒一轮，依次刷新 5 个控件
  （旧 id：`data.n0` / `data.n1` / `data.n2` / `data.t1` / `data.t0`；新 id 见 §0），数值每轮自增，状态文本在
  `READY / MEASURE / PAUSE / LOGIN` 之间循环，并同步打 TX 日志。

### 预期现象（屏上应看到的节奏）

| 秒 | n0 | n1 | n2 | t1 | t0 |
|---|---|---|---|---|---|
| 1 | 1 | 2 | 3 | 4 | READY |
| 2 | 2 | 3 | 4 | 5 | MEASURE |
| 3 | 3 | 4 | 5 | 6 | PAUSE |
| 4 | 4 | 5 | 6 | 7 | LOGIN |
| 5 | 5 | 6 | 7 | 8 | READY |

### 结果

- [x] **合格**（用户确认）—— 控件每秒刷新正常，`data.` 前缀 + `.txt` 的三级写法有效。
  本版控件为 8 个（新增状态栏、报警栏、电量、时钟；其中状态栏发命令字 `reset`/`start`/`stop`，报警栏 id 仍是占位），
  刷新节奏改为：数值 200 ms（测量中）、时钟/电量/报警栏 1 秒（常开；报警栏每秒都发）、状态栏变化才发。
  注：当时的控件编号已全部作废，现行编号见 §0。

## 3. T3 — 上电/复位后第一条命令被吞（**旧版缺陷，已随接收链路一并移除**）

- **日期**：2026-09-14
- **现象**：上电或复位后第一次发 `@用户名@login`，单片机不解析、无任何响应；日志只有驱动层的两行 RX dump。
- **根因**：屏在**上电/复位时会回传一帧 `1A FF FF FF`**。这三个字节既不是行尾（`\r`/`\n`）也不是 `/n`，
  所以永远不会被切行，一直赖在行缓冲里；等用户发第一帧命令时被追加到后面，交给解析函数的字符串首字符是 `0x1A`，
  整帧被丢弃 —— **只有"上电后第一条"被吃掉**。
- **当时的修复**（旧版 `service/screen`，两道防护）：行缓冲为空时只接受 `@`，其它字节直接丢；
  解析时从行内第一个 `@` 开始。
- **结果**：✅ 当时已修（用户确认"上电后第一次登录就能成功"）。
- **本版现状**：固件**根本不收屏数据**（`driver/screen_uart` 分配了 256 字节 RX 缓冲但固件从不读取，也没有接收任务），该问题不可能再出现；本条仅作留档。

## 4. T4 — U盘文件"找不到 / 打不开"（**缺陷，已修复，结论仍然有效**）

- **日期**：2026-09-14
- **现象**：串口日志显示"创建文件成功、长度 48 字节、回读验证通过"，但把 U 盘插到电脑上**看不到文件 / 打不开**。
- **排查过程**：
  1. 把 `F:\ESP32\niaio\project`（参考工程，**已验证可跑**）的 `ch376_spi.c` 与本工程逐行 diff → 底层 SPI/命令函数逐字节一致；
  2. 定位到差异在**文件名大小写**。
- **根因**：
  - 参考工程写的是 **`/ASD.TXT`（全大写 8.3）**；旧版写的是 **小写**；
  - CH376 的 `SET_FILE_NAME (0x2F)` 按手册**只支持 8.3 短文件名且字母必须大写**。
    传小写时芯片**能用同样字符串打开回来**（日志看着"成功"），但写进目录项的名字是坏的 → 电脑上找不到/打不开。
- **修复**（`service/storage/storage.c` 的 `make_fname()`）：文件名统一转成 `/大写8.3.TXT`；
  同时**新增"落盘验证"**：建完文件后**重新挂载(0x31)再打开**（强制丢掉芯片内部缓存、重读磁盘），能读到长度才算真的落盘。
- **结果**：✅ 已修 —— 文件出现在 `H:\`，能正常打开（用户确认）。
- **本版现状**：文件名由 `U%07lu` 生成（`/U0000001.TXT` 等），天然是大写 8.3；`make_fname()` 仍负责规范化。
  落盘验证保留在 `storage_create_session()` / `storage_ensure_session()` 里。
- **顺带修掉的另一个坑**：`media_sync()` 早期只发 `0x30 DISK_CONNECT` 而**没补 `0x31 MOUNT`**。
  `0x30` 会让芯片重新枚举 USB 设备、**作废已挂载的 FAT 上下文**，于是后续文件操作一律返回 `0x42 ERR_MISS_FILE`
  —— **哪怕文件就在盘上**。现已改成 **`0x30` 之后无条件补 `0x31`**。

## 5. T5 — 拔插 U 盘后已删除的文件"复活"（**缺陷，已修复，结论仍然有效**）

- **日期**：2026-09-14
- **现象**：在电脑上删掉的文件，把 U 盘插回板子后又出现了；同时板子新写的文件在电脑上找不到。
- **根因**：CH376 挂载后把 **FAT 表 + 根目录扇区缓存在芯片内部 RAM**，板子只在开机时挂载一次，之后不检测介质。
  U 盘在电脑上改过再插回，芯片仍拿**过期的目录缓存**读写 → 旧目录扇区被写回（删除失效）、新目录项被覆盖（文件丢失）、
  FAT 两边交替写导致错乱。
- **修复**：`service/storage/media_sync()` —— 在需要开始新动作时（**必须没有文件打开**）做一次 `0x30 检测 + 0x31 重挂载`。
- **结果**：✅ 已修。
- **另一处"删了又出现"的原因**：开机的 `TEST.TXT` 自检每次上电都重建文件，**已删除该自检**。
- **本版现状**：`media_sync()` 保留，调用点在新测量分配文件（`storage_create_session()`）与断盘恢复（`storage_ensure_session()`）；
  掉盘后由 `app/S1` 每 5 秒重试一次。

## 6. T6 — 速率 7 秒无新滴归零（**待现场确认**）

- **日期**：2026-09-14
- **需求**：串口屏显示的实时速率，如果 **7 秒没有新数据**就显示 0
- **实现**：`service/urine` 里用 `drop_last_time_us()`（硬件滴落时刻）判定
  ```c
  if (last != 0 && (now - last) > URINE_RATE_ZERO_MS * 1000ULL)
      s_meas.rate_mlh = 0.0f;        /* URINE_RATE_ZERO_MS = 7000 */
  ```
- **预期**：滴几滴后停止，等 8~10 秒 → 屏上 `data.t1`（实时速率）变 `0.0`；再滴一滴立刻恢复
- **结果**：⬜ 待现场确认
  > 注意：**只有测量中**（`app/S1` 在跑）才会刷新屏上数据；另外确认烧的是本工程固件
  > （用工程根目录的 `flash.bat`，别点 IDE 的 Flash —— IDE 的"当前工程"曾指向参考工程）

## 7. 结论与遗留

- ✅ 串口屏**发送链路**（MCU → 屏）正常；旧版 5 控件验证通过，本版为 **8 个控件**（含状态栏命令字、报警栏单字母、电量、时钟）。
- ✅ 屏 → MCU 方向的旧协议（`@用户名@login/start/stop/reset`）已整体废弃：**本版固件不接收屏数据**，操作全部由 GPIO8/GPIO9 两个实体按键完成。
- ✅ 旧版 S1~S4 / `login` 状态机已被**三态状态机**取代：待开始 → 测量中（S1）→ 暂停（S2），K2 任意状态复位（状态栏刷成 `reset`）。
- ✅ U 盘读写正常（大写 8.3 文件名、建/追加/每分钟一行、落盘验证、拔插重挂载、缺盘容错）。
- ⬜ 速率 7s 归零待现场确认。
- ⬜ 每滴体积未标定：当前默认 `URINE_DROP_ML_DEFAULT = 0.5 ml`（`service/urine/urine.h`），**必须按实物标定**。
- ⬜ **屏端映射与字库**需配合：MCU 只发 ASCII（状态栏命令字 `reset`/`start`/`stop`、报警栏单字母 `A`~`E`），屏上要显示的**中文全部由屏端自己映射**（状态三态 + 报警五态），TJC 工程字库要包含这些词。
- ⬜ **报警栏**的控件名仍是占位值，**待 HMI 工程确定**（其余 7 个已定稿；只需改 `screen.h` 的 `SCR_CTRL_*` 宏）。

### 最常踩的坑（按发生频率）

| 现象 | 原因 |
|---|---|
| 改了半天没效果 | **烧错工程** —— IDE 的"当前工程"指向 `F:\ESP32\niaio\project`，用根目录 `flash.bat` |
| 文件在电脑上看不到 | 文件名不是**大写 8.3**（已修）；或拔盘前没让文件正常关闭 |
| 屏上控件没反应 | 控件名与 HMI 工程不一致（状态栏 `data.t4` 已定稿，报警栏 `data.t5` 仍是占位）；或帧结尾少了三个 `FF` |
| 中文显示乱码 | 屏端字库/字符编码未配置（固件按 UTF-8 原样发送） |
