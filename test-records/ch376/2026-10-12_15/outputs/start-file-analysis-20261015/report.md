# 开始、暂停继续与重复建文件：代码复核

日期：2026-10-15。仅做源码分析及控制流模型验证；未改正式 third 或测试副本固件源码，未编译/烧录新固件，未访问串口或U盘。本目录的 C 文件是分析夹具，不是交付固件。

## 结论

固件确实存在重复分配文件与同名重建的路径，不能把问题全部归于U盘。但“复位后开始”和“暂停后继续”须分开：前者按既定需求属于新检测，应新建文件；后者必须保留同一检测文件。正常暂停继续分支没有调用新建入口，异常存储重试可能在继续后间接触发创建。

## 1. 正常状态机

`git/third_logtest_20261012/main/app/monitor/monitor.c:224` 的 APP_IDLE → START 调用 S1_storage_start，再清零计量并进入测量；复位回到 APP_IDLE，所以下次开始新建是预期行为。

同文件239行 APP_PAUSED → START 仅恢复计时、采集与测量状态，不调用 S1_storage_start。235行测量中重复 START 幂等。正式 third 此段相同。

## 2. 已创建但验证失败，重试可能分配新编号

`main/service/storage/storage.c:240–255` 中先执行创建、写表头、关闭、重挂载回读，全部成功后才把 candidate 返回到上层 stem。如果文件已经物理生成，但后续验证失败，上层 s_session 仍为空。

`main/app/S1/S1.c:267–282` 重试根据 s_session 是否为空判断“恢复旧会话”还是“重新分配文件”。空标识每5秒走一次 storage_create_session；下次若查到上次文件已存在便跳过编号，造成同一次检测出现多个编号文件。暂停期间 S1_run 不执行；到期重试可延迟到继续后的首次运行，因此表象可能是“暂停后开始新建”。这只在存储异常/尚未就绪等条件下发生，不是每次正常继续都新建。

实机归档日志 `outputs/third-acceptance-20261014/串口日志_20261014_112326.log`：6473ms U0000001 表头回读失败；11503ms重新进入“新建测量文件”；13033ms成功建立 U0000002。第一次暂停是26873ms，说明本次编号增长发生在暂停之前，不能据此说由暂停按钮直接触发。

## 3. 追加/恢复收到 0x42 后自动创建，可能覆盖已有记录

测试副本 `main/service/storage/storage.c:324–337`：追加打开失败只要返回0x42就调用 create_with_header，写入新表头。恢复入口290–304行有同样行为。正式 third 的追加293行附近与恢复228行以后也有这两条创建路径；不是仅B版新增的风险。

这两条路径把“芯片本次报告未找到”直接当作“应当创建”，没有保护已确认存在的会话。若返回码来自目录/芯片上下文异常，就会对已知文件发出 FILE_CREATE；该命令具备覆盖同名文件的语义，可能丢失历史数据。

实机69573ms打开 U0000002 返回0x42，69593ms打印“文件不存在，现场创建”。文件首簇从初次创建的8变为264。此时没有新的开始状态变化；它是一分钟追加中的同名重建。文件名不变不代表原文件与历史内容被保留。

## 修复原则（本轮尚未实施）

1. 把检测会话身份与文件创建/验证状态分开：同一次检测只确定一次文件标识；创建结果不确定时先验证这个候选文件，不重新选号，也不无条件再次 CREATE。候选存在时还须确认是否属于本次创建，避免误用历史记录。
2. 显式的新检测才允许分配新文件。暂停继续、存储恢复、分钟追加只能查找并追加同一会话。已知会话打开返回0x42时先报错、做有界恢复/复查，不能静默创建覆盖。真缺失或换盘需要单独明确的策略。
3. 保留并排查底层“已存在却打开失败”和首簇7→263读回不一致；防止重建可以阻止进一步丢失记录，但不等于修复了底层文件访问。
4. 日志标明命令、状态变化、会话标识、创建/重试原因与创建次数；验收应包含一次开始、至少三分钟、两次暂停继续、复位后重新开始，并验证只有复位后的开始产生第二个检测文件，原文件历史行保留。还须做故障注入：首次写表头后校验失败、已知文件打开0x42，确认不换号、不覆盖。

## 本轮验证

运行 `check_paths.py`，把实际 monitor/S1 与实际 storage C 分别接入可控存储/CH376桩，使用现有 ESP GCC 编译到 RV32 并执行。6项全部确认当前代码行为：

- 正常暂停继续不增建文件，重复 START 不增建，复位再开始会调用第二次创建。
- 首次创建失败后会话标识为空，暂停跨过重试期限后继续，首次测量循环再次调用创建。
- 已知会话写入失败，暂停跨过重试期限后继续，会调用恢复入口。
- 真实存储层创建/写表头成功但回读失败，会把空标识返回给上层。
- 真实存储层追加打开0x42，会调用创建及表头写入。
- 真实存储层恢复打开0x42，会调用创建及表头写入。

这些用例证明缺陷路径，不能当作修复通过或硬件复现；CH376返回0x42的底层原因仍未确定。测试前后8个受检源码（正式/测试版各monitor、S1、storage、CH376 SPI）SHA256一致。完整结果及哈希见 results.json。
